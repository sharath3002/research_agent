The agent

built on Composio's own SDK + MCP
01

Composio-native check

For every app, first ask Composio's own toolkit catalog if it's already there. If yes, its auth scheme and tool count become ground-truth evidence instead of a guess.

02

Docs research pass

A Composio session (Anthropic provider) hands Claude a real scraping tool. It opens the app's actual docs, not a cached memory of them, before answering.

03

Forced structured output

Claude must call a submit_research tool with a strict JSON schema - no prose to re-parse, no missing fields.

04

MCP-exposed session

The same session is a live MCP endpoint (session.mcp.url), so the pipeline is drivable from any MCP client, not just this script.

Where a human was needed: apps with no public docs (contact-sales-only products), pricing pages that contradicted the API docs, and every case the blind second pass below disagreed on - those got a manual doc check, not a tie-break guess.

What moved the number

Two independent loops, run before trusting a row:

  • Blind second pass - a fresh agent session re-derives the same app with zero visibility into pass 1. Disagreements get flagged, not averaged.
  • Human gold check - a random sample is hand-verified against the actual docs; that's the number reported here, not the agent's own confidence score.

Full methodology and the exact disagreement list: verify.py in the repo.
